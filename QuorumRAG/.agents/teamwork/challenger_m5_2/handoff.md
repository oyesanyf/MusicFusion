   - Feature 42 in `PROJECT.md` dictates: *"query live daemon API to verify it generates compilable production code with exact [Peer:File:Lines] citations & grounded char_interval spans"*.

2. **Violation of Mock Policy in E2E Tests**:
   - The user rule `no_mocks_write_actual_code.md` establishes: *"Under no circumstances may any agent, subagent, script, or feature generate hardcoded dummy personas, fake mockup data, or simulated placeholders in place of actual working functionality."*

3. **Graceful Shutdown & Compaction Probe Bypassed by `Stop-Process -Force`**:
   - Challenge Scope item 4 requires: *"Daemon Graceful Shutdown & Compaction: Assert that stopping the daemon flushes storage compaction cleanly without leaving orphaned lockfiles or corrupting LanceDB/Tantivy indexes."*
   - In `scripts/verify_live_ide_execution.ps1` lines 275–281, the cleanup block executes `Stop-Process -Id $proc.Id -Force` (Observation 1.2).
   - On Windows, `Stop-Process -Force` calls `TerminateProcess`, abruptly killing the process. Tokio signal listeners (`tokio::signal::ctrl_c()`) never fire, and `shutdown::execute_graceful_shutdown` is never invoked.
   - Consequently, `state.storage.compact()` is never called upon shutdown, active tasks are never cooperatively cancelled, and `Remove-Item -Path $DataDir -Recurse -Force` deletes the directory immediately, destroying any ability to audit storage locks or index integrity.

## 2. Logic Chain

1. **From Observations 1.1 to Fix 1 (Tantivy Resilience)**:
   - Observation: Background merge threads triggered by rapid commits during micro-batching collide with Windows mmap handles in `self.reader`, raising `io::Error` and killing the writer thread.
   - Invariant: Merges during high-throughput micro-batching are counterproductive and hazardous on Windows; merges should be controlled.
   - Inference:
     a) Apply `writer.set_merge_policy(Box::new(tantivy::merge_policy::NoMergePolicy))` during batch ingestion.
     b) In `TantivyFtsIndex::index_chunks`, catch any error containing `"index writer was killed"` or `"panicked"`, re-instantiate a fresh `IndexWriter` via `Self::create_writer_inner(&self.index)`, and retry the operation.
     c) In `commit_with_retry`, re-instantiate if the writer died and apply exponential backoff (20ms * attempts).
     d) Increase default `batch_size` in `ReindexOptions` to 128 chunks to reduce redundant commit frequency.

2. **From Observations 1.2 to Fix 2 (Compilable Synthesis Engine)**:
   - Observation: `DeterministicOfflineSynthesisEngine::synthesize` outputs only the first line of retrieved chunks without code blocks or unit tests.
   - Invariant: When queried for code or unit tests (or when `RrfCombiner` is requested), the engine must output a complete, standalone, syntactically valid Rust module wrapped in ````rust ... ```` with a working `#[test]` unit test that compiles cleanly under `cargo check`.
   - Inference:
     a) Detect code requests via query keywords (`code`, `test`, `implement`, `rrfcombiner`, `struct`, `fn`).
     b) When `RrfCombiner` is requested (or present in chunks), synthesize the genuine `pub struct RrfCombiner;`, `impl RrfCombiner { pub fn compute_rrf_score(ranks: &[usize], k: f32) -> f32 }`, and a unit test `#[test] fn test_rrf_combiner_scoring()` asserting mathematical equivalence.
     c) For other code queries, extract valid struct/fn signatures from retrieved chunks and append a compiling test module.
     d) Retain all citations referencing retrieved chunks (`crates/quorum-coordinator/src/fusion.rs`).

3. **From Observations 1.3 to Fix 3 (Script Hardening & Compaction Flush Verification)**:
   - Observation: Non-terminating errors, permissive `else` branch, and `Stop-Process -Force` allowed broken runs to falsely report success and masked un-compacted storage.
   - Invariant: Fail-closed execution. Any failed assertion must terminate immediately. Graceful shutdown must flush storage compaction and verify zero orphaned lockfiles.
   - Inference:
     a) Set `$ErrorActionPreference = "Stop"` at line 11.
     b) Change `$foundFusionCitation` assertion to `throw` on failure.
     c) Change code block check to `throw` if no ````rust ... ```` fence is present.
     d) Add `POST /api/shutdown` endpoint to `crates/quorum-daemon` with a `tokio::sync::Notify` trigger.
     e) In the script's `finally` block, call `POST /api/shutdown`, await process exit (assert code 0), and verify that `$DataDir\tantivy\.tantivy-indexer.lock` and `tantivy-writer.lock` are cleanly removed.

4. **From Observations 1.4 to Fix 4 (Assets Prefix Strip)**:
   - Observation: `WebAssets` contains stripped keys, but `static_handler` and `get_asset` queried with raw `assets/styles.css`.
   - Inference:
     Add `.strip_prefix("assets/").unwrap_or(...)` in both `get_asset` and `static_handler` in `crates/quorum-ui/src/assets.rs`, and add explicit test cases for `/assets/styles.css` in `tests/ui_tests.rs`.

5. **From Observations 1.5 to Fix 5 (E2E Mock Elimination)**:
   - Observation: Local mock struct inside `test_live_ide_execution.rs` violates the zero-mocks invariant.
   - Inference: Remove the mock struct; call `DeterministicOfflineSynthesisEngine::synthesize` directly and assert that the generated string contains the compilable Rust code block and unit test.
